🧠 Os 4 Pilares da Lógica de Programação Universal

Independentemente de você programar em Python, C, Java ou COBOL, todo computador do planeta opera sob os mesmos quatro princípios lógicos elementares (Modelo de von Neumann).

📥

1. Entrada, Processamento e Saída (IPO)

Entrada: Dados recebidos do teclado, rede ou disco. Processamento: Cálculos lógicos e aritméticos na CPU. Saída: Exibição na tela, gravação em banco ou envio pela rede.

📦

2. Variáveis, Tipos e Memória

Variáveis são caixas identificadas na memória RAM. Cada tipo (Inteiro, Real, Texto, Booleano) reserva um número específico de bytes para representar informação com precisão.

🔀

3. Tomada de Decisão (Estruturas Condicionais)

A bifurcação lógica: avaliar proposições booleanas (Verdadeiro/Falso) com operadores lógicos (E, OU, NÃO) para desviar o fluxo de execução para caminhos distintos.

🔁

4. Repetição e Iteração (Laços / Loops)

Execução repetida de um bloco instrucional enquanto uma condição for satisfeita ou ao longo de uma sequência de itens, evitando repetição manual de instruções.

📌 Enunciado: Crie uma classe Biblioteca com uma lista de livros (dicionários com titulo, autor e disponivel). Implemente métodos: emprestar(titulo) que marca o livro como indisponível, e listar_disponiveis() que retorna apenas os livros disponíveis usando list comprehension.

Defina self.livros = [] no construtor. Para adicionar livros, crie um método adicionar(titulo, autor) que usa append() com um dicionário.
Para filtrar: [l for l in self.livros if l['disponivel']]. Isso retorna apenas os livros onde o campo disponivel for True.
class Biblioteca:
    def __init__(self):
        self.livros = []

    def adicionar(self, titulo, autor):
        self.livros.append({"titulo": titulo, "autor": autor, "disponivel": True})

    def emprestar(self, titulo):
        for livro in self.livros:
            if livro["titulo"] == titulo and livro["disponivel"]:
                livro["disponivel"] = False
                return f"'{titulo}' emprestado com sucesso!"
        return "Livro não encontrado ou indisponível."

    def listar_disponiveis(self):
        return [l["titulo"] for l in self.livros if l["disponivel"]]

🔬 Conceitos Técnicos Avançados — Python
GIL — Global Interpreter Lock

O GIL é um mutex que protege o estado interno do CPython, permitindo apenas uma thread Python por vez. Isso elimina race conditions, mas limita paralelismo CPU-bound. Soluções: multiprocessing, asyncio (I/O-bound) ou Python 3.13 free-threaded.

Dunder Methods — Protocolo de Dados

Métodos como __repr__, __eq__, __hash__, __len__ e __iter__ permitem que seus objetos se comportem como tipos nativos do Python. É o "Data Model" que Luciano Ramalho explora profundamente em Fluent Python.

Metaclasses e Descritores

Metaclasses controlam a criação de classes (são "fábricas de classes"). Descritores (__get__/__set__) implementam a lógica por trás de @property, @classmethod e frameworks como Django ORM e SQLAlchemy.

asyncio — Event Loop Nativo

Desde Python 3.4, o asyncio traz programação assíncrona com async/await. FastAPI usa isso para servir milhares de requisições simultâneas sem threads. uvloop é um loop ultra-rápido baseado em libuv (mesma base do Node.js).

Type Hints e Mypy

PEP 484 (Python 3.5+) introduziu anotações de tipo. O Mypy valida estaticamente sem executar o código. Em Python 3.12+, use type alias = list[int] (nova sintaxe). Ferramentas: Pyright (Microsoft), Basedpyright, Mypy.

Python Packaging Moderno

pyproject.toml é o padrão PEP 517/518 que substituiu setup.py. Ferramentas recomendadas: UV (Astral, 2024 — 10–100× mais rápido que pip), Poetry (lock file + virtual envs), Hatch (PyPA oficial).

🔗 Promise Chain vs Async/Await

Uma Promise representa uma operação futura. O async/await é açúcar sintático que torna código assíncrono legível como código síncrono — mas por baixo ainda usa Promises.

📦 Módulos ES6 (import/export)

Permitem dividir o código em arquivos separados e importar apenas o necessário. Melhoram a manutenibilidade e permitem tree-shaking (eliminação de código morto).

// utils.js
export const soma = (a, b) => a + b;
// main.js

Segmentos de Memória em Detalhe

Text: código de máquina (read-only). Data: variáveis globais inicializadas. BSS: globais não-inicializadas (zeradas pelo loader). Stack: frames de funções (automático, LIFO). Heap: alocação manual (malloc/free). Compreender esses segmentos é essencial para debugging.

Undefined Behavior (UB)

C tem dezenas de comportamentos "indefinidos" — o compilador pode gerar qualquer código (ou nenhum) nesses casos: dereferência de ponteiro nulo, overflow de inteiro com sinal, acesso fora de array, leitura de variável não-inicializada. GCC e Clang com -fsanitize=undefined detectam UB em runtime.

Preprocessador e Macros

O preprocessador C (#define, #ifdef, #include) roda antes do compilador, fazendo substituição textual. Macros como #define MAX(a,b) ((a)>(b)?(a):(b)) são expandidas inline. Prefira static inline funções e const a macros com valores quando possível.

Alinhamento e Padding de Structs

O compilador insere bytes de padding entre campos de struct para alinhar dados em endereços múltiplos do seu tamanho. Um struct { char c; int i; } ocupa 8 bytes (não 5) por causa do padding de 3 bytes. Use __attribute__((packed)) ou reordene campos para economizar memória.

setjmp/longjmp — Exceções em C

C não tem exceções nativas. setjmp/longjmp (em <setjmp.h>) simulam um "goto" não-local salvando e restaurando o contexto da pilha. Usado internamente por algumas implementações de exceção em C++ e em sistemas embarcados sem C++.

Restrict e Otimizações de Aliasing

A palavra-chave restrict (C99) informa ao compilador que dois ponteiros não se sobrepõem ("não fazem aliasing"), permitindo vetorização automática (SIMD). As funções de string da glibc usam restrict para atingir performance de montagem.

🏦 6. COBOL — A Lógica de Negócios e Processamento em Massa

Criada em 1959 liderada por Grace Hopper
🧠 Lógica Prévia Fundamental: Como COBOL Raciocina?
  • As 4 Divisões Estruturais Rígidas: Todo programa COBOL é dividido em:
    1. IDENTIFICATION DIVISION (metadados do programa);
    2. ENVIRONMENT DIVISION (mapeamento do hardware e arquivos);
    3. DATA DIVISION (declaração estrita de registros por níveis hierárquicos: 01, 05, 10);

  • Picture Clauses (PIC) & Precisão Decimal Exata: COBOL não usa ponto flutuante binário (que causa erros de arredondamento em centavos). Cada variável possui máscara exata: PIC 9(5)V99 significa 5 dígitos inteiros e 2 decimais com precisão aritmética absoluta.

1
Por que COBOL parece inglês?

Foi criado para ser lido por gerentes de negócio, não só por programadores. MOVE 100 TO WS-SALDO é literalmente "mova o valor 100 para a variável WS-SALDO". A intenção é máxima clareza.

O que é PIC 9(5)V99?

PIC (Picture Clause) define o formato exato de uma variável. 9(5) = 5 dígitos inteiros. V = ponto decimal virtual. 99 = 2 casas decimais. Assim 12345.67 é representado sem erro de ponto flutuante.

3
Como praticar COBOL hoje?

Instale o GnuCOBOL (opensource.gnucobol.com) ou use o IBM Z Xplore (gratuito!) — plataforma online da IBM para aprender COBOL e mainframe com certificação.

🔬 Conceitos Técnicos Avançados — COBOL
VSAM — Virtual Storage Access Method

O sistema de arquivos mais usado em mainframes IBM. VSAM suporta KSDS (Key-Sequenced: acesso por chave, como um índice B-tree), ESDS (Entry-Sequenced: sequencial) e RRDS (Relative-Record: acesso direto por número). COBOL acessa VSAM via ORGANIZATION IS INDEXED e ACCESS MODE.

CICS — Customer Information Control System

Monitor de transações online da IBM. COBOL com CICS usa comandos como EXEC CICS SEND MAP para telas 3270 e EXEC CICS READ INTO para leitura transacional. O CICS gerencia filas de transações com altíssima disponibilidade (99.999%).

DB2 e SQL Embutido

COBOL pode executar SQL diretamente com EXEC SQL SELECT ... INTO :variavel END-EXEC. O pré-compilador DB2 substitui o SQL por chamadas à API do banco antes da compilação. Host variables (prefixadas com :) passam valores entre COBOL e SQL de forma type-safe.

JCL — Job Control Language

Cada programa COBOL em z/OS é submetido via JCL: um script declarativo que define o job (JOB), executa programas (EXEC PGM=) e aloca conjuntos de dados (DD). Um Job completo de processamento de folha pode ter 50+ cartões JCL encadeados em passos (STEP).

EBCDIC vs ASCII

Mainframes IBM usam EBCDIC (Extended Binary Coded Decimal Interchange Code), não ASCII. 'A' em ASCII = 0x41, mas em EBCDIC = 0xC1. Todo dado transferido entre mainframes e sistemas modernos precisa de conversão explícita — uma fonte comum de bugs em integrações.

COMP e COMP-3 — Formatos Binários

COMP (binary): inteiro em formato binário nativo, eficiente para aritmética. COMP-3 (packed decimal): armazena 2 dígitos BCD por byte — o formato de altíssima precisão para valores monetários sem os erros de ponto flutuante binário. A escolha de PIC e USAGE impacta diretamente performance e precisão.

🗄️ 8. SQL — A Lógica da Teoria dos Conjuntos e Álgebra Relacional

Edgar F. Codd (1970) & IBM System R (1974)
🧠 Lógica Prévia Fundamental: Como SQL Raciocina?
  • Paradigma Declarativo: Em linguagens imperativas você diz COMO fazer passo a passo com laços; em SQL você apenas diz O QUE deseja receber, e o Otimizador de Consultas do SGBD calcula o plano mais veloz.
  • Álgebra Relacional & JOINs: Tabelas são conjuntos de tuplas. Um INNER JOIN é a interseção matemática de duas tabelas conectadas por uma chave estrangeira (FK).
  • Propriedades ACID: Atomicidade (tudo ou nada), Consistência (regras válidas), Isolamento (transações simultâneas sem interferência) e Durabilidade (dados persistem após gravação).

SELECT
    a.nome AS estudante,
    COUNT(m.curso_id) AS total_cursos,
    ROUND(AVG(m.nota_final), 2) AS media_geral
FROM alunos a
INNER JOIN matriculas m ON a.id = m.aluno_id

🎯 Índices B-Tree & Performance

Sem índices, o banco faz um Full Table Scan (O(N)), lendo todas as linhas do disco. Um índice B-Tree permite buscas em O(log N), acelerando consultas em milhões de registros de minutos para milissegundos.

Relacionais: PostgreSQL, MySQL, Oracle, IBM Db2, SQL Server.
NoSQL / Complementares: Redis (Cache em RAM), MongoDB (Documentos JSON).

✅ Boas Práticas de Banco de Dados
  • Nunca concatene texto do usuário em queries (vulnerabilidade crítica de SQL Injection); use sempre Prepared Statements / Consultas Parametrizadas.
  • Evite SELECT * em aplicações de produção (pesquise apenas as colunas necessárias para economizar largura de banda e memória).
  • Normalize o banco até a 3ª Forma Normal (3FN) para evitar redundância e inconsistência de dados.
⚠️ Erro Comum: Falha de JOIN & Produto Cartesiano

Omitir a cláusula ON tabelaA.id = tabelaB.ref_id em um JOIN faz o banco cruzar todas as linhas de A com todas as linhas de B, gerando milhões de registros falsos e derrubando a CPU do servidor.

Subqueries, CTEs, Window Functions e Transações
🔍 Subqueries e CTEs

Uma subquery é uma consulta dentro de outra. Uma CTE (WITH) é uma subquery nomeada que melhora a legibilidade e pode ser referenciada múltiplas vezes.

WITH top_alunos AS (
  SELECT * FROM alunos WHERE nota >= 9
)
SELECT nome FROM top_alunos
WHERE turma = 'A';
📊 Window Functions

Calculam valores sobre um conjunto de linhas relacionadas sem colapsar os resultados em grupos. Permitem ranking, acumulados e comparações linha a linha.

SELECT nome, salario,
  RANK() OVER (PARTITION BY depto
            ORDER BY salario DESC) AS posicao
FROM funcionarios;
🔒 ACID e Transações

BEGIN TRANSACTION agrupa múltiplas operações em uma única unidade atômica. COMMIT persiste; ROLLBACK desfaz tudo se qualquer etapa falhar — garantia essencial em operações bancárias.

BEGIN;
UPDATE contas SET saldo = saldo - 100
  WHERE id = 1;
UPDATE contas SET saldo = saldo + 100
  WHERE id = 2;
COMMIT;

🔬 Conceitos Técnicos Avançados — SQL
Plano de Execução (EXPLAIN)

EXPLAIN ANALYZE mostra o plano real do otimizador: Seq Scan (leitura linha a linha), Index Scan, Nested Loop, Hash Join. Leia o plano de baixo para cima. "cost=0.00..8.27 rows=185" significa custo estimado e linhas esperadas. Tools: pgAdmin, explain.dalibo.com.

MVCC — Multi-Version Concurrency Control

PostgreSQL e MySQL InnoDB usam MVCC: em vez de locks, mantêm múltiplas versões de cada linha. Cada transação vê um snapshot do banco no momento do início. Permite reads não-bloqueantes. Old versions são removidas pelo VACUUM (Postgres) ou purge thread (MySQL).

Particionamento de Tabelas

Particionar divide uma tabela grande em subtabelas físicas: PARTITION BY RANGE (data_criacao) cria partições por mês. Queries com filtro na coluna de partição ignoram partições irrelevantes (partition pruning), reduzindo I/O de 100× em tabelas de bilhões de registros.

Índices Avançados no PostgreSQL

Além do B-tree padrão: GIN (full-text search, arrays, JSON), GiST (geometria espacial com PostGIS), BRIN (colunas ordenadas naturalmente, como timestamps), Hash (igualdade exata), ivfflat (pgvector para busca por similaridade de embeddings de IA).

Recursive CTEs

CTEs recursivas permitem consultar estruturas hierárquicas (árvores, grafos) sem programação: WITH RECURSIVE hierarquia AS (SELECT ... UNION ALL SELECT ... JOIN hierarquia ...). Usadas para organogramas, categorias aninhadas, caminhos em grafos e cálculos de série Fibonacci.

Temporal Tables (SQL:2011)

Tabelas temporais mantêm histórico automático de alterações: SYSTEM_TIME rastreia quando o banco modificou a linha; APPLICATION_TIME rastreia períodos de validade de negócio. Permitem queries como "qual era o salário deste funcionário em 15/03/2022?" sem código extra.

📌 Enunciado: Crie uma classe PHP UsuarioRepository que receba um PDO no construtor e implemente: 1) criar(string $nome, string $email, string $senhaHash): int que insere um usuário e retorna o ID gerado; 2) buscarPorEmail(string $email): ?array que retorna os dados do usuário ou null se não existir. Use Prepared Statements em ambos.

$stmt = $this->db->prepare('INSERT INTO usuarios (nome, email, senha) VALUES (:nome, :email, :senha)'); após execute(), use $this->db->lastInsertId() para retornar o ID.

<?php
class UsuarioRepository {
    public function __construct(private readonly PDO $db) {}

    public function criar(string $nome, string $email, string $senhaHash): int {
        $stmt = $this->db->prepare(
            'INSERT INTO usuarios (nome, email, senha) VALUES (:nome, :email, :senha)'
        );
        $stmt->execute([':nome' => $nome, ':email' => $email, ':senha' => $senhaHash]);
        return (int) $this->db->lastInsertId();
    }

    public function buscarPorEmail(string $email): ?array {
        $stmt = $this->db->prepare(
            'SELECT id, nome, email FROM usuarios WHERE email = :email LIMIT 1'
        );
        $stmt->execute([':email' => $email]);
        $result = $stmt->fetch(PDO::FETCH_ASSOC);
        return $result ?: null;
    }
}

🔬 Conceitos Técnicos Avançados — PHP
Zend Engine e Opcache

O Zend Engine 4 (PHP 8) compila PHP para bytecode Zend, que é executado pela VM. O Opcache armazena o bytecode compilado em memória compartilhada, eliminando a recompilação a cada requisição — melhoria de 30-50% de throughput com configuração simples.

PHP-FPM — FastCGI Process Manager

PHP-FPM gerencia pools de processos PHP que respondem requisições do Nginx/Apache via protocolo FastCGI. Configurar os pools corretamente (pm.max_children, pm.start_servers) é crucial para performance sob carga. Um processo PHP por requisição é isolado e stateless.

Fibers (PHP 8.1) — Corrotinas Nativas

Fibers são corrotinas cooperativas: $fiber = new Fiber(fn => { Fiber::suspend('valor'); });. Diferente de goroutines (Go) ou async/await (JS), Fibers são explicitamente suspensas e resumidas. ReactPHP e Swoole usam para I/O não-bloqueante sem extensões externas.

Enums (PHP 8.1) — Tipos Enumerados

Enums puros e backed enums: enum Status: string { case Ativo = 'A'; case Inativo = 'I'; }. Backed enums podem ser serializados para banco de dados. Implementam interfaces, têm métodos e constantes — muito além dos define() constantes do PHP legado.

Readonly Properties e Constructor Promotion

PHP 8.0 trouxe Constructor Property Promotion: public function __construct(private readonly string $nome) declara e atribui o atributo em uma linha. PHP 8.2 adicionou Readonly Classes — todos os atributos são implicitamente readonly, ideal para DTOs e Value Objects.

Psalm e PHPStan — análise estática

Psalm (Vimeo) e PHPStan são ferramentas de análise estática que encontram bugs antes de executar o código. PHPStan tem 10 níveis de rigor; nível 9 verifica tipos em todos os pontos. Integre com GitHub Actions para barrar PRs com erros de tipo em CI/CD.

🏛️ 11. Banco de Dados — MySQL, PostgreSQL e Modelagem Relacional

MySQL (1995 / Sun/Oracle) · PostgreSQL (1996 / PGDG)
🧠 Lógica Prévia Fundamental: Como Projetar um Banco de Dados?
  • Modelo Entidade-Relacionamento (MER): Antes de criar qualquer tabela, modele as entidades do mundo real (Cliente, Pedido, Produto), seus atributos e as relações entre elas (1:N, N:M). Um bom diagrama ER evita redesenhos dolorosos.
  • Normalização (1FN → 3FN): Processo de eliminar redundâncias. 1FN: sem grupos repetitivos (arrays em colunas). 2FN: atributos dependem da chave inteira. 3FN: atributos não dependem de outros atributos não-chave.
  • Chaves Primárias (PK) e Estrangeiras (FK): A PK identifica unicamente cada linha. A FK cria a ponte de integridade referencial entre tabelas — o banco rejeita orphan records automaticamente.
  • Índices como Livro de Índice Analítico: Um índice B-Tree funciona como o índice de um livro grosso: em vez de ler todas as páginas (Full Scan), você vai direto à página correta em O(log n).

CREATE TABLE clientes (
    id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    nome        VARCHAR(100) NOT NULL,
    email       VARCHAR(120) UNIQUE NOT NULL,
    criado_em   TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE produtos (
    id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    nome        VARCHAR(150) NOT NULL,
    preco       DECIMAL(10,2) NOT NULL CHECK (preco > 0),
    estoque     INT UNSIGNED DEFAULT 0
);

CREATE TABLE pedidos (
    id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    cliente_id  INT UNSIGNED NOT NULL,
    total       DECIMAL(12,2) NOT NULL DEFAULT 0,
    status      ENUM('PENDENTE','PAGO','ENTREGUE','CANCELADO') DEFAULT 'PENDENTE',
    criado_em   TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_pedido_cliente
        FOREIGN KEY (cliente_id) REFERENCES clientes(id) ON DELETE RESTRICT
);

-- 2. Índice para acelerar consultas por status e data
CREATE INDEX idx_pedidos_status_data
    ON pedidos(status, criado_em DESC);

-- 3. View para Relatório de Faturamento por Cliente
CREATE VIEW vw_faturamento_clientes AS
SELECT
    c.nome,
    COUNT(p.id)      AS total_pedidos,
    SUM(p.total)     AS faturamento,
    MAX(p.criado_em) AS ultimo_pedido
FROM clientes c
LEFT JOIN pedidos p ON c.id = p.cliente_id
   AND p.status = 'PAGO'
GROUP BY c.id, c.nome
ORDER BY faturamento DESC;

✅ Boas Práticas de Modelagem e Performance
  • Crie índices nas colunas usadas em WHERE, JOIN ON e ORDER BY — mas não exagere: índices custam espaço e tornam INSERTs/UPDATEs mais lentos.
  • Use EXPLAIN ANALYZE (PostgreSQL) ou EXPLAIN (MySQL) antes de otimizar uma query — veja o plano de execução real do otimizador.
  • Prefira LEFT JOIN quando um lado pode não ter registros correspondentes e você precisa mantê-los no resultado (ex: clientes sem pedidos).
⚠️ Erro Comum: N+1 Query Problem

Buscar uma lista de 100 pedidos e depois fazer uma query separada para cada pedido buscar o cliente resulta em 101 queries. Solução: use JOIN para trazer tudo em uma única query ou IN (...) com os IDs em lote.

📌 Enunciado: Dado o schema: funcionarios(id, nome, salario, depto_id) e departamentos(id, nome), escreva queries para: 1) Listar o nome do departamento e a média salarial, apenas para departamentos com mais de 3 funcionários, ordenado pela maior média; 2) Encontrar o funcionário de maior salário de CADA departamento usando Window Functions (RANK()).

GROUP BY d.id, d.nome agrupa por departamento. HAVING COUNT(f.id) > 3 filtra após o agrupamento. ROUND(AVG(f.salario), 2) calcula a média.
RANK() OVER (PARTITION BY depto_id ORDER BY salario DESC) — PARTITION BY reinicia o ranking para cada departamento. Filtre com WHERE posicao = 1 em uma CTE.
-- Query 1: Média por departamento (mínimo 4 funcionários)
SELECT d.nome AS departamento,
       ROUND(AVG(f.salario), 2) AS media_salarial,
       COUNT(f.id) AS total
FROM departamentos d
INNER JOIN funcionarios f ON d.id = f.depto_id
GROUP BY d.id, d.nome
HAVING COUNT(f.id) > 3
ORDER BY media_salarial DESC;

-- Query 2: Top 1 salário por departamento
WITH ranking AS (
  SELECT f.nome, f.salario, d.nome AS depto,
         RANK() OVER (PARTITION BY f.depto_id ORDER BY f.salario DESC) AS posicao
  FROM funcionarios f
  JOIN departamentos d ON d.id = f.depto_id
)
SELECT depto, nome, salario
FROM ranking
WHERE posicao = 1;

O que é uma Chave Primária (PK)?

É um campo que identifica unicamente cada linha de uma tabela. Como o CPF para um cidadão brasileiro — nunca pode se repetir. Em SQL: id INT PRIMARY KEY AUTO_INCREMENT cria um número automático único para cada registro.

O que é uma Chave Estrangeira (FK)?

É o campo que cria a ligação entre duas tabelas. Na tabela pedidos, a coluna cliente_id referencia o id da tabela clientes. É como uma "ponte" que garante que um pedido só existe para clientes reais.

3
MySQL vs PostgreSQL para iniciantes

Ambos são excelentes. MySQL é mais simples para começar (XAMPP já vem com ele). PostgreSQL é mais robusto e poderoso. Para iniciantes: MySQL. Para projetos sérios: PostgreSQL. Instale o DBeaver (grátis) como cliente visual.

🔬 Conceitos Técnicos Avançados — Banco de Dados
Teorema CAP e Sistemas Distribuídos

Num sistema distribuído, você só pode garantir 2 das 3 propriedades: Consistency (todos veem os mesmos dados), Availability (sistema sempre responde) e Partition Tolerance (funciona com falhas de rede). PostgreSQL é CP; Cassandra é AP; bancos NewSQL (CockroachDB, Spanner) tentam superar essa limitação.

Write-Ahead Log (WAL)

Toda modificação é primeiro escrita no WAL antes de ser aplicada no arquivo de dados. Se o servidor cair, o PostgreSQL "reaply" o WAL para recuperar um estado consistente. O WAL também é a base para replicação streaming — replicas recebem o WAL do primário em tempo quase real.

B-Tree Internals

Um B-Tree de profundidade 4 em PostgreSQL com fator de ramificação de 200 pode indexar 200⁴ = 1,6 bilhões de registros com apenas 4 I/Os por busca. A raiz (1 bloco) e nível 1 (200 blocos) são quase sempre mantidos em cache de buffer pool, tornando buscas por chave primária praticamente O(1) na prática.

Connection Pooling — PgBouncer

PostgreSQL cria um processo OS (~5MB) por conexão. Um app com 1.000 usuários simultâneos com conexões diretas consumiria 5GB só em overhead de conexões. PgBouncer (transaction mode) mantém um pool de 20-50 conexões reais e multiplexa milhares de conexões de aplicação — economizando recursos críticos.

Sharding e Federação

Sharding divide dados horizontalmente em múltiplos servidores por chave de particionamento (user_id % N). Consistência entre shards requer transações distribuídas 2PC. Alternativas modernas: Citus (sharding automático no PostgreSQL), PlanetScale (MySQL serverless com sharding) e CockroachDB (NewSQL com sharding nativo).

Event Sourcing vs State Stores

Em vez de armazenar apenas o estado atual, Event Sourcing grava cada evento que causou uma mudança. O estado é reconstruído pela projeção dos eventos. Permite auditoria completa, replay de eventos e múltiplas visões do mesmo dado. Apache Kafka é o backbone de muitas arquiteturas de Event Sourcing em produção.

Em Rust, você pode emprestar uma referência (&valor) sem transferir posse. Lifetimes ('a) garantem que a referência não sobreviva ao dono — eliminando dangling pointers em tempo de compilação.

fn maior<'a>(x: &'a str, y: &'a str) -> &'a str {
  if x.len() > y.len() { x } else { y }
}
⚙️ Go — Interfaces Implícitas

Go não usa implements. Se um tipo tem os métodos de uma interface, ele a satisfaz automaticamente. Isso cria um polimorfismo flexível sem acoplamento de hierarquia.

type Stringer interface { String() string }
type Produto struct { Nome string }
func (p Produto) String() string {
  return "Produto: " + p.Nome
}
📡 Go — select para múltiplos Channels

O select em Go é como um switch para canais. Permite aguardar múltiplos canais simultaneamente e executar o caso que estiver pronto primeiro — essencial para orquestração de microsserviços.

select {
case msg := <-ch1:
  fmt.Println("ch1:", msg)
case msg := <-ch2:
  fmt.Println("ch2:", msg)
case <-time.After(1 * time.Second):
  fmt.Println("Timeout!")
}

📌 Enunciado (Rust): Escreva uma função soma_pares(nums: &[i32]) -> i32 que receba uma fatia de inteiros por referência (sem transferir posse) e retorne a soma apenas dos números pares usando iteradores (.iter().filter().sum()).

📌 Enunciado (Go): Crie uma função contarPalavras(texto string) map[string]int que receba uma string, divida por espaços e retorne um map com a contagem de cada palavra.

nums.iter().filter(|&&x| x % 2 == 0).sum() — o &&x faz dupla desreferência porque filter recebe uma referência de referência em slices.
strings.Fields(texto) divide por qualquer espaço/newline. Itere com for _, w := range palavras { contagem[w]++ }.
// Rust
fn soma_pares(nums: &[i32]) -> i32 {
    nums.iter().filter(|&&x| x % 2 == 0).sum()
}

// Go
import "strings"
func contarPalavras(texto string) map[string]int {
    contagem := make(map[string]int)
    for _, w := range strings.Fields(texto) {
        contagem[w]++
    }
    return contagem
}

2006

Graydon Hoare começa Rust como projeto pessoal

Frustrado com um bug de segmentação no elevador de seu prédio (software C/C++), Graydon Hoare começa Rust. A ideia: eliminar categorias inteiras de bugs de memória sem sacrificar performance.

2007

Rob Pike, Ken Thompson e Robert Griesemer iniciam Go no Google

Três lendas da computação — inclusive Ken Thompson (criador do Unix e C) — iniciam Go enquanto esperavam um build de 45 minutos do código C++ do Google. Go seria simples, rápido de compilar e naturalmente concorrente.

2009

Go 1.0 anunciado publicamente

Google anuncia Go no Google I/O. Goroutines, channels, garbage collector, inferência de tipos e compilação extremamente rápida definem a filosofia: simplicidade radical.

2015

Rust 1.0 — estabilidade e Ownership oficial

Rust 1.0 é lançado com a Mozilla Foundation como patrocinadora. O sistema de ownership e borrow checker são estabilizados. Rust começa a ganhar adoção no setor de segurança de sistemas.

2022

Rust entra no Kernel do Linux

Linux 6.1 inclui suporte oficial a Rust para módulos do kernel — o primeiro código não-C no kernel desde 1991. Linus Torvalds aprova pessoalmente. Marca histórica na história da computação de sistemas.

2024

Governo dos EUA recomenda Rust — NSA, CISA e ONCD

O ONCD (Office of the National Cyber Director) publica documento recomendando Rust e outras linguagens memory-safe em vez de C/C++ para sistemas críticos, citando que 70% das vulnerabilidades críticas são erros de memória.

🔬 Conceitos Técnicos Avançados — Rust & Go
Rust: Ownership em Detalhe

Cada valor tem exatamente um "dono". Quando o dono sai de escopo, o valor é dropped automaticamente (RAII). Move transfere posse. Clone copia. Borrow (&T) dá acesso temporário imutável; Mutable borrow (&mut T) dá acesso exclusivo mutável. O borrow checker garante: uma &mut ou N &, nunca ambos simultaneamente.

Rust: Traits e Generics com Monomorphization

Traits definem comportamentos: impl Display for MinhaStruct. Generics com trait bounds (fn imprime<T: Display>(v: T)) são monomorphizados: o compilador gera uma versão concreta para cada tipo usado — zero overhead runtime, mas binários maiores.

Go: Goroutine Scheduler (G-M-P)

O scheduler do Go usa o modelo G-M-P: Goroutines (tarefas leves), Machines (threads OS) e Processors (contextos de execução, um por CPU). Work-stealing: Ps roubam goroutines de outros Ps ociosos. Escala para milhões de goroutines com apenas algumas threads OS.

Rust: async/await com Tokio

Rust async é zero-cost: futures são state machines geradas em tempo de compilação sem alocações heap por padrão. Tokio é o runtime mais popular: single-threaded (tokio::main) ou multi-threaded com work-stealing. Axum (web framework) e Tonic (gRPC) são construídos sobre Tokio.

Go: Context e Cancelamento

context.Context é a forma idiomática de propagar cancelamento, timeouts e valores entre goroutines em Go. ctx, cancel := context.WithTimeout(ctx, 5*time.Second) cancela automaticamente operações que excedam 5s. Todo handler HTTP, query de banco e chamada RPC deve aceitar e propagar context.

Rust: unsafe e FFI

Blocos unsafe { } desabilitam as garantias do borrow checker localmente para operações que o compilador não pode verificar: dereferência de raw pointers, chamadas FFI, acesso a static mutável. O princípio: encapsule unsafe em abstrações seguras que exponham APIs safe ao resto do código.

Rust: Linguagem de sistemas sem GC — usada no Linux Kernel, Android, AWS e navegadores
Go: Linguagem de cloud-native — base do Docker, Kubernetes e Terraform

📚 Glossário de Pedagogia & Programação

        


        

          

            
Algoritmo

            
Sequência finita, ordenada e não-ambígua de instruções lógicas que resolve um problema específico ou executa uma tarefa.

          

          

            
Ponteiro (Pointer)

            
Variável que armazena diretamente o endereço físico de memória hexadecimal de outra variável em vez de seu valor numérico.

          

          

            
Garbage Collector (GC)

            
Mecanismo automático de gerenciamento de memória que rastreia e descarta objetos que não possuem mais referências ativas no programa.

          

          

            
Andaime (Scaffolding)

            
Estratégia pedagógica que oferece suporte passo a passo ao estudante (pseudocódigo guiado) removido gradualmente com o ganho de autonomia.

          

          

            
Ownership (Rust)

            
Regra que estipula que cada recurso na memória possui um único proprietário estrito em tempo de compilação, eliminando bugs de memória sem Garbage Collector.

          

          

            
Divisões COBOL

            
Estrutura clássica de 4 seções (Identification, Environment, Data e Procedure) que separa rigidamente dados e procedimentos em sistemas contábeis.
