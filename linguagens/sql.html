Linguagem Declarativa / Banco de Dados

🗄️ SQL

A linguagem universal dos dados. Nascida da teoria relacional de Edgar Codd (1970) e concretizada no projeto IBM System R (1974), o SQL tornou-se o padrão ANSI/ISO indiscutível para consultar, transformar e governar informações em qualquer escala.

1970 Teoria Relacional (Codd)
1986 Padrão ANSI / ISO
#1 Linguagem de Dados
Declarativa Diga o "quê", não o "como"

História & Evolução

Mais de 50 anos de solidez, adaptando-se da era dos mainframes à moderna computação em nuvem.

1970

Modelo Relacional (Edgar F. Codd, IBM)

Edgar Frank Codd publica o lendário artigo "A Relational Model of Data for Large Shared Data Banks" no laboratório da IBM, fundamentando os bancos de dados na teoria matemática dos conjuntos e na lógica de predicados.

1974

SEQUEL no IBM System R

Donald Chamberlin e Raymond Boyce criam a SEQUEL (Structured English QUEry Language) para o projeto experimental System R da IBM. O nome foi abreviado posteriormente para SQL por questões de direitos de marca.

1979

Primeiro SGBD Comercial (Oracle)

A Relational Software Inc. (fundada por Larry Ellison, Bob Miner e Ed Oates, hoje Oracle Corporation) lança o Oracle V2, o primeiro SGBD relacional comercial baseado em SQL para sistemas PDP-11 e VAX.

1986

SQL-86: O Padrão ANSI

O American National Standards Institute (ANSI) ratifica o SQL como padrão formal, seguido pela ISO em 1987. A indústria unifica a sintaxe básica de DDL e DML entre fornecedores.

1992

SQL-92 (SQL2): A Grande Revisão

Consolidação do SQL moderno: padronização da sintaxe explícita de junções (JOIN ... ON), novos tipos de dados (VARCHAR, DATE, TIME), subqueries na cláusula FROM e integridade referencial com restrições CASCADE.

1999

SQL:1999 (SQL3): CTEs & Recursão

Adoção de Common Table Expressions (WITH), consultas recursivas para hierarquias de grafos/árvores, suporte a triggers, tipos definidos pelo usuário (UDT) e recursos orientados a objetos.

2003

SQL:2003: Window Functions

Revolução analítica com a introdução das Window Functions (OVER, ROW_NUMBER, RANK), além de geradores automáticos de sequências (IDENTITY) e suporte a documentos XML.

2016

SQL:2016: Suporte Nativo a JSON

Inclusão oficial de operadores e funções nativas de manipulação JSON, tabelas temporais com versionamento histórico de registros e funções de agregação polimórficas.

Hoje

PostgreSQL 16+ & MySQL 8+

O SQL domina tanto transações OLTP de altíssima escala quanto data warehouses analíticos OLAP (Snowflake, BigQuery, DuckDB), integrando busca vetorial com IA (pgvector), particionamento distribuído e execução paralela.

Conceitos Fundamentais

Explore as principais construções da linguagem, com explicações objetivas e códigos prontos para o dia a dia.

A instrução SELECT define as colunas retornadas, FROM indica a tabela de origem, WHERE filtra as linhas antes de qualquer processamento e ORDER BY ordena o resultado final.

01_select_basico.sql
-- Consulta clientes ativos de SP ou RJ com saldo acima de R$ 1.000
SELECT
    id,
    nome,
    email,
    cidade,
    saldo_pontos AS pontos_fidelidade,
    criado_em
FROM
    clientes
WHERE
    ativo = TRUE
    AND estado IN ('SP', 'RJ')
    AND saldo_pontos >= 1000
    AND email IS NOT NULL
ORDER BY
    saldo_pontos DESC,
    nome ASC
LIMIT 20 OFFSET 0;

Os JOINs conectam tabelas através de chaves primárias e estrangeiras. INNER JOIN traz apenas correspondências em ambos os lados; LEFT JOIN preserva todos os registros da tabela à esquerda mesmo sem par à direita.

02_joins.sql
-- INNER JOIN: Somente pedidos com clientes válidos
-- LEFT JOIN: Todos os clientes, mesmo aqueles sem nenhum pedido
SELECT
    c.id AS cliente_id,
    c.nome AS cliente,
    p.id AS pedido_id,
    COALESCE(p.valor_total, 0.00) AS valor_total,
    COALESCE(p.status, 'SEM_PEDIDO') AS status_pedido
FROM
    clientes c
LEFT JOIN
    pedidos p ON c.id = p.cliente_id
WHERE
    c.ativo = TRUE;

O GROUP BY agrupa linhas com valores idênticos para calcular métricas agregadas. O filtro HAVING é aplicado após o cálculo da agregação, diferente do WHERE que filtra antes.

03_group_by_having.sql
-- Resumo de vendas por categoria de produto em 2024
SELECT
    cat.nome AS categoria,
    COUNT(DISTINCT p.id) AS total_pedidos,
    SUM(ip.quantidade) AS itens_vendidos,
    ROUND(AVG(ip.preco_unitario), 2) AS preco_medio,
    SUM(ip.quantidade * ip.preco_unitario) AS faturamento_bruto
FROM
    categorias cat
INNER JOIN produtos prod ON cat.id = prod.categoria_id
INNER JOIN itens_pedido ip ON prod.id = ip.produto_id
INNER JOIN pedidos p ON ip.pedido_id = p.id
WHERE
    p.status = 'CONCLUIDO'
    AND p.data_pedido >= '2024-01-01'
GROUP BY
    cat.nome
HAVING
    SUM(ip.quantidade * ip.preco_unitario) > 50000.00
ORDER BY
    faturamento_bruto DESC;

As Common Table Expressions (CTEs) com a palavra-chave WITH tornam consultas complexas limpas, modulares e reutilizáveis, substituindo subqueries aninhadas de difícil leitura.

04_cte_with.sql
-- Identifica clientes com faturamento superior à média geral de todos os clientes
WITH GastosPorCliente AS (
    SELECT
        cliente_id,
        COUNT(id) AS qtd_pedidos,
        SUM(valor_total) AS total_gasto
    FROM
        pedidos
    WHERE
        status = 'CONCLUIDO'
    GROUP BY
        cliente_id
),
MediaGeral AS (
    SELECT AVG(total_gasto) AS media_ticket_cliente
    FROM GastosPorCliente
)
SELECT
    c.nome,
    c.email,
    g.qtd_pedidos,
    g.total_gasto,
    ROUND(m.media_ticket_cliente, 2) AS media_geral
FROM
    GastosPorCliente g
CROSS JOIN
    MediaGeral m
INNER JOIN
    clientes c ON g.cliente_id = c.id
WHERE
    g.total_gasto > m.media_ticket_cliente
ORDER BY
    g.total_gasto DESC;

Funções de janela executam cálculos analíticos através de partições de dados sem colapsar as linhas como o GROUP BY. Permitem rankings, médias móveis e comparações temporais.

05_window_functions.sql
-- Ranking e evolução diária das vendas por vendedor
SELECT
    vendedor_id,
    data_venda,
    valor_venda,
    -- Número sequencial único da venda por vendedor
    ROW_NUMBER() OVER (
        PARTITION BY vendedor_id ORDER BY data_venda ASC
    ) AS num_venda_vendedor,
    -- Valor da venda anterior para comparar crescimento
    LAG(valor_venda, 1, 0) OVER (
        PARTITION BY vendedor_id ORDER BY data_venda ASC
    ) AS valor_venda_anterior,
    -- Soma acumulada de vendas ao longo do tempo
    SUM(valor_venda) OVER (
        PARTITION BY vendedor_id ORDER BY data_venda ASC
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS total_acumulado_vendedor
FROM
    vendas;

Índices (como árvores B-Tree) aceleram buscas de O(N) para O(log N). O comando EXPLAIN ANALYZE detalha o plano de execução, custo estimado e tempo real de varredura (Index Scan vs Seq Scan).

06_indices_explain.sql
-- 1. Criação de índice composto otimizado para filtros em pedidos
CREATE INDEX idx_pedidos_cliente_status_data
ON pedidos (cliente_id, status, data_pedido DESC);

-- 2. Índice parcial: indexa somente pedidos pendentes (tamanho reduzido em disco)
CREATE INDEX idx_pedidos_pendentes
ON pedidos (data_pedido)
WHERE status = 'PENDENTE';

-- 3. Inspecionando o plano de execução e estatísticas de I/O no PostgreSQL
EXPLAIN ANALYZE
SELECT
    id, valor_total, data_pedido
FROM
    pedidos
WHERE
    cliente_id = 4821
    AND status = 'CONCLUIDO'
ORDER BY
    data_pedido DESC
LIMIT 10;

Exemplos Práticos Completos

Consultas SQL do mundo real preparadas para cenários de alta produtividade, analytics e arquitetura de banco de dados.

Pipeline analítico completo de faturamento: consolida múltiplos JOINs, calcula margem de contribuição, segmenta por região e rankeia os clientes de maior valor gerado.

analise_vendas_avancada.sql
/*
   RELATÓRIO EXECUTIVO DE VENDAS
   Objetivo: Calcular métricas de margem, ticket médio e fidelidade
   Recursos: CTEs múltiplas, INNER/LEFT JOINs, agregação e condicionais CASE
*/

WITH VendasDetalhadas AS (
    SELECT
        p.id AS pedido_id,
        p.cliente_id,
        c.nome AS cliente_nome,
        c.estado AS uf,
        p.data_pedido,
        prod.id AS produto_id,
        prod.nome AS produto_nome,
        cat.nome AS categoria_nome,
        ip.quantidade,
        ip.preco_unitario,
        prod.custo_unitario,
        (ip.quantidade * ip.preco_unitario) AS receita_bruta,
        (ip.quantidade * (ip.preco_unitario - prod.custo_unitario)) AS lucro_bruto
    FROM
        pedidos p
    INNER JOIN clientes c ON p.cliente_id = c.id
    INNER JOIN itens_pedido ip ON p.id = ip.pedido_id
    INNER JOIN produtos prod ON ip.produto_id = prod.id
    INNER JOIN categorias cat ON prod.categoria_id = cat.id
    WHERE
        p.status = 'CONCLUIDO'
        AND p.data_pedido >= DATE_TRUNC('year', CURRENT_DATE)
),
ResumoPorCliente AS (
    SELECT
        cliente_id,
        cliente_nome,
        uf,
        COUNT(DISTINCT pedido_id) AS total_pedidos,
        SUM(quantidade) AS total_itens,
        SUM(receita_bruta) AS faturamento_total,
        SUM(lucro_bruto) AS lucro_total,
        ROUND(AVG(receita_bruta), 2) AS ticket_medio_item
    FROM
        VendasDetalhadas
    GROUP BY
        cliente_id, cliente_nome, uf
)
SELECT
    cliente_id,
    cliente_nome,
    uf,
    total_pedidos,
    total_itens,
    faturamento_total,
    lucro_total,
    ROUND((lucro_total / NULLIF(faturamento_total, 0)) * 100, 2) AS margem_lucro_pct,
    CASE
        WHEN faturamento_total >= 50000 THEN 'Tier Diamante (VIP)'
        WHEN faturamento_total >= 20000 THEN 'Tier Ouro'
        WHEN faturamento_total >= 5000  THEN 'Tier Prata'
        ELSE 'Tier Bronze'
    END AS segmento_cliente
FROM
    ResumoPorCliente
ORDER BY
    faturamento_total DESC
LIMIT 50;

Dashboard analítico de Recursos Humanos: ranking salarial por departamento via DENSE_RANK(), desvio salarial em relação à média departamental com AVG() OVER() e variação para o funcionário anterior com LAG().

dashboard_rh_window_functions.sql
/*
   DASHBOARD ANALÍTICO DE RH & SALÁRIOS
   Calcula hierarquias de remuneração, médias departamentais e dispersão
*/

WITH EstatisticasSalariais AS (
    SELECT
        f.id AS funcionario_id,
        f.nome AS funcionario,
        f.cargo,
        d.nome AS departamento,
        f.salario,
        -- Ranking denso de remuneração dentro do departamento
        DENSE_RANK() OVER (
            PARTITION BY f.departamento_id
            ORDER BY f.salario DESC
        ) AS rank_depto,
        -- Média salarial global daquele departamento
        AVG(f.salario) OVER (
            PARTITION BY f.departamento_id
        ) AS media_salarial_depto,
        -- Salário imediatamente anterior na ordem de remuneração
        LAG(f.salario) OVER (
            PARTITION BY f.departamento_id
            ORDER BY f.salario DESC
        ) AS salario_degrau_acima,
        -- Total de colaboradores no departamento
        COUNT(*) OVER (
            PARTITION BY f.departamento_id
        ) AS total_funcionarios_depto
    FROM
        funcionarios f
    INNER JOIN
        departamentos d ON f.departamento_id = d.id
    WHERE
        f.ativo = TRUE
)
SELECT
    funcionario_id,
    funcionario,
    cargo,
    departamento,
    salario,
    rank_depto,
    ROUND(media_salarial_depto, 2) AS media_depto,
    ROUND(salario - media_salarial_depto, 2) AS diferenca_para_media,
    COALESCE(ROUND(salario_degrau_acima - salario, 2), 0.00) AS distancia_para_topo,
    total_funcionarios_depto
FROM
    EstatisticasSalariais
ORDER BY
    departamento ASC,
    salario DESC;

Modelagem relacional completa (DDL) para uma plataforma de e-commerce moderna com chaves primárias, chaves estrangeiras com integridade referencial, constraints avançadas, índices estratégicos e uma View analítica.

schema_ecommerce.sql
-- 1. TABELA DE CATEGORIAS
CREATE TABLE categorias (
    id SERIAL PRIMARY KEY,
    nome VARCHAR(100) NOT NULL UNIQUE,
    slug VARCHAR(120) NOT NULL UNIQUE,
    ativo BOOLEAN DEFAULT TRUE,
    criado_em TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 2. TABELA DE PRODUTOS COM CONSTRAINTS E CHECK
CREATE TABLE produtos (
    id BIGSERIAL PRIMARY KEY,
    categoria_id INT NOT NULL REFERENCES categorias(id) ON DELETE RESTRICT,
    sku VARCHAR(50) NOT NULL UNIQUE,
    nome VARCHAR(255) NOT NULL,
    preco NUMERIC(12, 2) NOT NULL CHECK (preco >= 0),
    custo_unitario NUMERIC(12, 2) NOT NULL CHECK (custo_unitario >= 0),
    estoque INT NOT NULL DEFAULT 0 CHECK (estoque >= 0),
    ativo BOOLEAN DEFAULT TRUE,
    criado_em TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 3. TABELA DE CLIENTES
CREATE TABLE clientes (
    id BIGSERIAL PRIMARY KEY,
    cpf_cnpj VARCHAR(18) NOT NULL UNIQUE,
    nome VARCHAR(150) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE,
    estado CHAR(2) NOT NULL,
    ativo BOOLEAN DEFAULT TRUE,
    criado_em TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 4. TABELA DE PEDIDOS
CREATE TABLE pedidos (
    id BIGSERIAL PRIMARY KEY,
    cliente_id BIGINT NOT NULL REFERENCES clientes(id) ON DELETE CASCADE,
    data_pedido TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    status VARCHAR(30) NOT NULL DEFAULT 'PENDENTE'
        CHECK (status IN ('PENDENTE', 'PAGO', 'ENVIADO', 'CONCLUIDO', 'CANCELADO')),
    valor_total NUMERIC(12, 2) NOT NULL DEFAULT 0.00
);

-- 5. TABELA DE ITENS DO PEDIDO (N:N)
CREATE TABLE itens_pedido (
    id BIGSERIAL PRIMARY KEY,
    pedido_id BIGINT NOT NULL REFERENCES pedidos(id) ON DELETE CASCADE,
    produto_id BIGINT NOT NULL REFERENCES produtos(id) ON DELETE RESTRICT,
    quantidade INT NOT NULL CHECK (quantidade > 0),
    preco_unitario NUMERIC(12, 2) NOT NULL CHECK (preco_unitario >= 0),
    CONSTRAINT uk_pedido_produto UNIQUE (pedido_id, produto_id)
);

-- 6. ÍNDICES DE ALTA PERFORMANCE
CREATE INDEX idx_produtos_categoria ON produtos (categoria_id);
CREATE INDEX idx_pedidos_cliente_data ON pedidos (cliente_id, data_pedido DESC);
CREATE INDEX idx_itens_pedido_produto ON itens_pedido (produto_id);

-- 7. VIEW ANALÍTICA PARA CONSULTA RÁPIDA DE VENDAS
CREATE OR REPLACE VIEW vw_resumo_pedidos_detalhados AS
SELECT
    p.id AS pedido_id,
    p.data_pedido,
    p.status,
    c.id AS cliente_id,
    c.nome AS cliente_nome,
    c.email AS cliente_email,
    COUNT(ip.id) AS total_linhas_itens,
    SUM(ip.quantidade) AS total_unidades,
    SUM(ip.quantidade * ip.preco_unitario) AS valor_calculado
FROM
    pedidos p
INNER JOIN clientes c ON p.cliente_id = c.id
LEFT JOIN itens_pedido ip ON p.id = ip.pedido_id
GROUP BY
    p.id, p.data_pedido, p.status, c.id, c.nome, c.email;
