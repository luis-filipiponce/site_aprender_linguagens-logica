Contexto

História & Evolução

De uma extensão do C para a linguagem que molda toda a infraestrutura digital moderna — quatro décadas de inovação sem parar.

1979

C with Classes — Bjarne Stroustrup, Bell Labs

Stroustrup adiciona classes, herança e verificação de tipos mais rígida ao C, buscando combinar a expressividade de Simula com a performance do C.

1983

Renomeado C++

O operador de incremento ++ no próprio nome: uma versão melhorada do C. Adiciona funções virtuais, sobrecarga de operadores, referências e const.

1998

C++98 — Primeiro padrão ISO, STL padronizada

A Standard Template Library (STL) — containers, algoritmos e iterators — é incorporada ao padrão, unificando o ecossistema.

2011

C++11 — A Grande Revolução Moderna

Move semantics, expressões lambda, smart pointers (unique_ptr, shared_ptr), dedução de tipos com auto, threads nativas, nullptr, range-for, e muito mais. Considerado o marco do C++ moderno.

2014

C++14 — Refinamentos do C++11

Lambdas genéricas, dedução de retorno de funções, std::make_unique, relaxamento de constexpr.

2017

C++17 — Structured Bindings, if constexpr, std::optional

Parallel STL, structured bindings, std::variant, std::any, std::filesystem e fold expressions tornaram o código muito mais expressivo.

2020

C++20 — Concepts, Ranges, Coroutines, Modules

A maior atualização desde C++11. Concepts permitem restrições semânticas em templates; Coroutines habilitam código assíncrono elegante; Modules eliminam problemas históricos com headers.

2023

C++23 — Refinamentos contínuos

std::expected, std::stacktrace, melhorias em ranges e formatação, e dezenas de correções e adições ao padrão.

Core

Conceitos Fundamentais

Os pilares que tornam C++ único — e que separam um programador médio de um especialista.

Resource Acquisition Is Initialization — o padrão mais importante de C++. Recursos (memória, arquivos, sockets) são vinculados ao ciclo de vida de objetos. Quando o objeto sai de escopo, o destrutor libera automaticamente o recurso.

C++ 
#include <memory>
#include <fstream>

void processFile(const std::string& path) {
    // unique_ptr: ownership exclusivo, liberação automática
    auto buffer = std::make_unique<int[]>(1024);

    // file fecha automaticamente ao sair do escopo
    std::ifstream file(path);
    if (!file) throw std::runtime_error("Não encontrado");

    // shared_ptr: ownership compartilhado com ref-count
    auto shared = std::make_shared<std::vector<int>>();
} // buffer, file e shared liberados aqui — sem leaks!

Templates permitem escrever código genérico que é instanciado em tempo de compilação, resultando em zero custo de runtime — diferente de generics via type erasure de outras linguagens.

C++ 
// Template de função — gerado para cada tipo em compile-time
template<typename T>
T max_val(T a, T b) { return a > b ? a : b; }

// Template de classe — container genérico
template<typename T, std::size_t N>
class Stack {
    T data[N];
    size_t top = 0;
public:
    void push(T val) { data[top++] = val; }
    T    pop()      { return data[--top]; }
};

// Instâncias distintas — sem overhead!
Stack<int, 64>    intStack;
Stack<double, 32> dblStack;

Introduzido no C++11, move semantics permite transferir ownership de recursos sem cópia — fundamental para performance com objetos grandes como vetores e strings.

C++ 
class Buffer {
    int* data;
    size_t size;
public:
    // Move constructor — "rouba" o recurso
    Buffer(Buffer&& other) noexcept
        : data(other.data), size(other.size) {
        other.data = nullptr; // invalida a fonte
    }
};

std::vector<Buffer> vec;
Buffer buf(1024);
vec.push_back(std::move(buf)); // sem cópia!

// Perfect forwarding preserva value category
template<typename T>
void wrapper(T&& arg) {
    target(std::forward<T>(arg));
}

A Standard Template Library oferece estruturas de dados e algoritmos prontos, todos com complexidade garantida pelo padrão e sem overhead de abstração.

C++ 
#include <vector>
#include <algorithm>
#include <map>
#include <ranges>   // C++20

std::vector<int> nums = {5,1,8,3,2};
std::sort(nums.begin(), nums.end());

// C++20 ranges — pipeline legível
auto evens = nums
    | std::views::filter([](int n){ return n%2==0; })
    | std::views::transform([](int n){ return n*2; });

std::map<std::string, int> scores;

C++11 trouxe suporte nativo a threads, mutexes e operações atômicas diretamente no padrão — sem dependência de APIs do sistema operacional.

C++ 
#include <thread>
#include <mutex>
#include <atomic>

std::atomic<int> counter{0};
std::mutex mtx;

void worker(int id) {
    counter.fetch_add(1, std::memory_order_relaxed);
    std::lock_guard<std::mutex> lock(mtx); // RAII lock
    // seção crítica protegida
}

int main() {
    std::thread t1(worker, 1);
    std::thread t2(worker, 2);
    t1.join(); t2.join();
}

C++ suporta polimorfismo em tempo de execução via vtables e virtual, além de polimorfismo estático via templates (zero overhead). A palavra-chave override (C++11) torna a intenção explícita e segura.

C++ 
class Shape {
public:
    virtual double area() const = 0; // pura virtual
    virtual ~Shape() = default;
};

class Circle : public Shape {
    double r;
public:
    Circle(double r) : r(r) {}
    double area() const override { return 3.14159 * r * r; }
};

// Polimorfismo via smart pointer
std::unique_ptr<Shape> s = std::make_unique<Circle>(5.0);
auto a = s->area(); // despacho virtual, sem leak

Além dos operadores lógicos (&&, ||, !) e do operador ternário (cond ? a : b), o C++20 introduziu o Three-Way Comparison Operator (conhecido como Spaceship Operator <=>), que gera automaticamente os 6 operadores relacionais (==, !=, <, <=, >, >=).

C++ 
#include <compare>
#include <iostream>

struct Ponto {
    int x, y;
    // Spaceship operator padrão (C++20): compara membro a membro
    auto operator<=>(const Ponto&) const = default;
};

int main() {
    Ponto p1{1, 2}, p2{1, 3};
    bool menor = (p1 < p2);  // true gerado automaticamente
    bool igual = (p1 == p2); // false

    // Operador ternário
    const char* msg = (p1 < p2) ? "p1 vem antes" : "p2 vem antes";
    std::cout << msg << "\n";
}

O C++17 trouxe if com inicializador integrado para limitar o escopo de variáveis. Já o if constexpr avalia a condição em tempo de compilação, descartando o ramo não utilizado sem gerar código de máquina.

C++ 
#include <map>
#include <type_traits>

// 1. if com inicializador local (C++17)
std::map<int, std::string> usuarios{{1, "Ana"}};
if (auto it = usuarios.find(1); it != usuarios.end()) {
    std::cout << "Encontrado: " << it->second << "\n";
}

// 2. if constexpr: compilado condicionalmente em compile-time
template<typename T>
auto processarValor(T valor) {
    if constexpr (std::is_pointer_v<T>) {
        return *valor; // só compila se for ponteiro
    } else {
        return valor;
    }
}

C++ desaconselha casts de estilo C (tipo)x em favor de 4 operadores explícitos e seguros: static_cast (conversões bem definidas em compile-time), dynamic_cast (downcasting seguro em tempo de execução com RTTI), const_cast (remover constância) e reinterpret_cast (reinterpretação bruta de bits).

C++ 
double pi = 3.14159;
int piInt = static_cast<int>(pi); // seguro e explícito

// dynamic_cast em hierarquia polimórfica
class Base { public: virtual ~Base() = default; };
class Derivada : public Base { public: void acao() {} };

Base* b = new Derivada();
if (Derivada* d = dynamic_cast<Derivada*>(b)) {
    d->acao(); // verificado com sucesso em runtime
}
delete b;

O range-based for (for (auto&& item : container)) é a forma idiomática e segura de percorrer coleções da STL sem perigo de erros de índice fora do limite (out-of-bounds).

C++ 
#include <vector>
#include <iostream>

std::vector<std::string> stacks = {"C++", "Rust", "Go"};

// Range-for com referência constante (sem cópia)
for (const auto& item : stacks) {
    std::cout << item << " ";
}

// Range-for com modificação
for (auto& item : stacks) {
    item += " 2024";
}

C++ suporta o bloco tradicional try / catch / throw com garantia de RAII (destrutores rodam automaticamente no desenrolar da pilha). Para código de altíssima performance onde exceções são desativadas (como em Game Dev), o C++23 introduziu std::expected<T, E> para erros do tipo monadic.

C++ 
#include <expected>
#include <string>

// C++23 std::expected: retorna o valor ou o erro de forma explícita
std::expected<double, std::string> dividir(double a, double b) noexcept {
    if (b == 0.0) return std::unexpected("Divisão por zero!");
    return a / b;
}

int main() {
    auto res = dividir(10.0, 2.0);
    if (res) {
        std::cout << "Resultado: " << *res << "\n";
    } else {
        std::cerr << "Erro: " << res.error() << "\n";
    }
}

O padrão de tipos embrulho (Wrappers) em C++ moderno é provido por tipos utilitários da STL como std::optional<T> (embrulha um valor ou estado vazio std::nullopt sem alocação de heap), std::variant<Ts...> (união tipada segura) e std::reference_wrapper<T> (permite guardar referências em containers STL).

C++ 
#include <optional>
#include <functional>
#include <vector>

// Wrapper de valor opcional
std::optional<std::string> buscarUsuario(int id) {
    if (id == 1) return "Luis Ponce";
    return std::nullopt; // ausente sem usar ponteiro nulo
}

int main() {
    auto user = buscarUsuario(1);
    std::cout << user.value_or("Desconhecido") << "\n";

    // reference_wrapper em container STL
    int x = 10, y = 20;
    std::vector<std::reference_wrapper<int>> refs = {x, y};
    refs[0].get() = 99; // altera x diretamente!
}

Hands-On

Exemplos Práticos

Código realista cobrindo os padrões mais usados no C++ moderno do dia a dia.

Classe de recurso com RAII completo: construtor, destrutor, move e copy semânticos corretos (Rule of Five).

C++ — unique_ptr & RAII 
#include <memory>
#include <iostream>
#include <stdexcept>

class FileResource {
    FILE* handle = nullptr;

public:
    explicit FileResource(const char* path, const char* mode) {
        handle = fopen(path, mode);
        if (!handle)
            throw std::runtime_error(std::string("Falha ao abrir: ") + path);
        std::cout << "✅ Arquivo aberto\n";
    }

    // Destrutor — liberação garantida (RAII)
    ~FileResource() {
        if (handle) { fclose(handle); std::cout << "🗑️  Arquivo fechado\n"; }
    }

    // Move constructor — transfere ownership
    FileResource(FileResource&& other) noexcept
        : handle(std::exchange(other.handle, nullptr)) {}

    // Move assignment
    FileResource& operator=(FileResource&& other) noexcept {
        if (this != &other) {
            if (handle) fclose(handle);
            handle = std::exchange(other.handle, nullptr);
        }
        return *this;
    }

    // Sem cópia — recurso único
    FileResource(const FileResource&)            = delete;
    FileResource& operator=(const FileResource&) = delete;

    FILE* get() const { return handle; }
};

int main() {
    // unique_ptr gerencia FileResource
    auto f = std::make_unique<FileResource>("data.txt", "r");
    // ... usa f->get() ...
    // sem necessidade de delete — RAII cuida de tudo
}

C++20 Concepts restringem templates com precisão semântica — erros de compilação legíveis e intenção documentada no código.

C++ — C++20 Concepts 
#include <concepts>
#include <numeric>
#include <vector>
#include <iostream>

// Concept: tipo deve ser numérico
template<typename T>
concept Numeric = std::integral<T> || std::floating_point<T>;

// Concept: container iterável com tipo numérico
template<typename C>
concept NumericRange =
    std::ranges::range<C> &&
    Numeric<std::ranges::range_value_t<C>>;

// Função restrita por concept — erro claro se violado
Numeric auto average(NumericRange auto const& range) {
    if (std::empty(range)) return 0.0;
    auto sum = std::reduce(
        std::begin(range), std::end(range));
    return static_cast<double>(sum) / std::size(range);
}

// Overload baseado em concept (não em SFINAE!)
template<Numeric T>
void print(T val) {
    std::cout << "Número: " << val << '\n';
}

int main() {
    std::vector<double> data = {3.0, 7.5, 2.5, 10.0};
    std::cout << "Média: " << average(data) << '\n'; // 5.75
    print(42);
    // print("oi"); — erro de compilação legível!
}

Thread pool simples usando std::thread, std::queue, mutex e condition variable — padrão clássico de concorrência em C++.

C++ — Thread Pool 
#include <thread>
#include <queue>
#include <mutex>
#include <condition_variable>
#include <functional>
#include <vector>

class ThreadPool {
    std::vector<std::thread>   workers;
    std::queue<std::function<void()>> tasks;
    std::mutex               queueMtx;
    std::condition_variable  cv;
    bool                     stop = false;

public:
    explicit ThreadPool(size_t n) {
        for (size_t i = 0; i < n; ++i)
            workers.emplace_back([this] {
                while (true) {
                    std::function<void()> task;
                    {
                        std::unique_lock lock(queueMtx);
                        cv.wait(lock, [this]{
                            return stop || !tasks.empty();
                        });
                        if (stop && tasks.empty()) return;
                        task = std::move(tasks.front());
                        tasks.pop();
                    }
                    task(); // executa fora do lock
                }
            });
    }

    void enqueue(std::function<void()> task) {
        { std::lock_guard lk(queueMtx); tasks.push(std::move(task)); }
        cv.notify_one();
    }

    ~ThreadPool() {
        { std::lock_guard lk(queueMtx); stop = true; }
        cv.notify_all();
        for (auto& w : workers) w.join();
    }
};

int main() {
    ThreadPool pool(4); // 4 workers
    for (int i = 0; i < 20; ++i)
        pool.enqueue([i]{ /* processa tarefa i */ });
} // pool destruído → workers finalizam

C++20/23 deixou o código mais declarativo: std::ranges com projeções e pipelines lazy, std::format/std::println com segurança de tipos e std::expected com operações monádicas para erros sem exceções.

C++23 — Ranges, format & expected 
#include <algorithm>
#include <expected>
#include <print>      // C++23: std::println (GCC 14+, Clang 18+, MSVC 19.37+)
#include <ranges>
#include <string>
#include <vector>

struct Produto { std::string nome; double preco; int estoque; };
enum class Erro { PrecoInvalido, EstoqueNegativo };

// std::expected<T,E>: valor OU erro tipado, sem exceção e sem códigos mágicos
std::expected<Produto, Erro> criar(std::string nome, double preco, int estoque) {
    if (preco <= 0)   return std::unexpected(Erro::PrecoInvalido);
    if (estoque < 0) return std::unexpected(Erro::EstoqueNegativo);
    return Produto{std::move(nome), preco, estoque};
}

int main() {
    std::vector<Produto> catalogo = {
        {"Teclado", 250.0, 12}, {"Mouse", 90.0, 0},
        {"Monitor", 1400.0, 4}, {"Webcam", 320.0, 7},
    };

    namespace rv = std::views;

    // Pipeline lazy: nada é calculado até a iteração; sem vetores temporários
    auto promo = catalogo
        | rv::filter([](const Produto& p) { return p.estoque > 0; })
        | rv::transform([](const Produto& p) { return p.preco * 0.9; })
        | rv::take(3);
    for (double v : promo) std::println("Promoção: R$ {:>8.2f}", v);

    // Ordenação por projeção: sem escrever comparador
    std::ranges::sort(catalogo, {}, &Produto::preco);
    for (const auto& [nome, preco, _] : catalogo)      // structured bindings (C++17)
        std::println("{:<10} R$ {:>8.2f}", nome, preco);

    // Encadeamento monádico: sem if aninhado
    auto r = criar("Headset", 199.9, 3)
        .transform([](Produto p) { p.preco *= 1.1; return p; })
        .transform([](const Produto& p) { return std::format("{} -> R$ {:.2f}", p.nome, p.preco); });

    if (r) std::println("{}", *r);
    else   std::println("Falha: código {}", static_cast<int>(r.error()));
}

Concorrência moderna sem armadilhas: std::jthread faz join automático e suporta cancelamento cooperativo via std::stop_token; std::latch sincroniza etapas e std::scoped_lock evita deadlock ao travar vários mutexes.

C++20 — jthread, stop_token & latch 
#include <atomic>
#include <chrono>
#include <iostream>
#include <latch>
#include <mutex>
#include <syncstream>
#include <thread>
#include <vector>

using namespace std::chrono_literals;

struct Conta { std::mutex m; long saldo = 0; };

// scoped_lock trava os DOIS mutexes de forma atômica: sem deadlock por ordem de aquisição
void transferir(Conta& de, Conta& para, long valor) {
    std::scoped_lock lk(de.m, para.m);
    de.saldo   -= valor;
    para.saldo += valor;
}

int main() {
    // 1) Cancelamento cooperativo: stop_token é injetado automaticamente
    std::atomic<int> ciclos{0};
    {
        std::jthread worker([&](std::stop_token st) {
            while (!st.stop_requested()) {
                ++ciclos;
                std::this_thread::sleep_for(10ms);
            }
            std::osyncstream(std::cout) << "worker encerrado de forma limpa\n";
        });
        std::this_thread::sleep_for(100ms);
        worker.request_stop();
    }   // destrutor do jthread: request_stop() + join() — nunca esquece o join

    // 2) latch: barreira de uso único — espera N tarefas concluírem
    constexpr int N = 4;
    std::latch prontos{N};
    std::atomic<long> total{0};
    std::vector<std::jthread> pool;
    for (int i = 1; i <= N; ++i)
        pool.emplace_back([&, i] { total += i * 100; prontos.count_down(); });
    prontos.wait();                              // bloqueia até count == 0

    Conta a, b; a.saldo = 1000;
    transferir(a, b, 250);
    std::osyncstream(std::cout) << "total=" << total << " a=" << a.saldo << " b=" << b.saldo << '\n';
}
// Compile com: g++ -std=c++20 -pthread -O2 main.cpp
