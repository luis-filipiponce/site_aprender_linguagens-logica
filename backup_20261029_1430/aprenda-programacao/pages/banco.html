🗄️ Banco de Dados

Um banco de dados é um sistema organizado para armazenar, gerenciar e recuperar informações de forma eficiente e persistente. Dados são a alma de qualquer software real.

SQL — Banco Relacional

Dados organizados em tabelas com linhas e colunas. Relacionamentos entre tabelas via chaves. O modelo mais usado no mundo corporativo há 50 anos — e continua sendo o padrão.

DDL — Definindo a estrutura

-- CREATE — criar tabelas CREATE TABLE usuarios ( id SERIAL PRIMARY KEY, -- auto incremento nome VARCHAR(100) NOT NULL, email VARCHAR(255) UNIQUE NOT NULL, senha_hash TEXT NOT NULL, criado_em TIMESTAMP DEFAULT NOW(), ativo BOOLEAN DEFAULT TRUE ); CREATE TABLE pedidos ( id SERIAL PRIMARY KEY, usuario_id INTEGER REFERENCES usuarios(id), -- chave estrangeira total NUMERIC(10,2) NOT NULL, criado_em TIMESTAMP DEFAULT NOW() );

DML — Manipulando dados

-- INSERT — inserir dados INSERT INTO usuarios (nome, email, senha_hash) VALUES ('Ana Silva', 'ana@email.com', '$2b$12$hash...'); -- SELECT — consultar SELECT id, nome, email FROM usuarios WHERE ativo = TRUE; -- UPDATE — atualizar UPDATE usuarios SET ativo = FALSE WHERE id = 42; -- DELETE — remover DELETE FROM usuarios WHERE criado_em < NOW() - INTERVAL '2 years';

JOINs — Combinando tabelas

-- INNER JOIN — apenas registros que casam nos dois lados SELECT u.nome, u.email, COUNT(p.id) AS total_pedidos, SUM(p.total) AS valor_total FROM usuarios u INNER JOIN pedidos p ON u.id = p.usuario_id WHERE u.ativo = TRUE GROUP BY u.id, u.nome, u.email HAVING SUM(p.total) > 1000 ORDER BY valor_total DESC LIMIT 10; -- LEFT JOIN — todos da esquerda, mesmo sem correspondência SELECT u.nome, p.total FROM usuarios u LEFT JOIN pedidos p ON u.id = p.usuario_id; -- usuários sem pedidos aparecerão com p.total = NULL

Índices — Acelerar buscas

-- Sem índice: PostgreSQL lê a tabela INTEIRA (seq scan) -- Com índice: acessa diretamente (index scan) — O(log n) CREATE INDEX idx_usuarios_email ON usuarios(email); CREATE INDEX idx_pedidos_usuario ON pedidos(usuario_id); -- Índice composto CREATE INDEX idx_pedidos_usuario_data ON pedidos(usuario_id, criado_em DESC);

ACID — Garantias de Transações

ACID garante que operações em banco de dados relacionais sejam confiáveis mesmo em caso de falha, concorrência ou erros.

A — Atomicidade

A transação é tudo ou nada. Se qualquer parte falhar, tudo é revertido. Nunca fica à metade.

C — Consistência

O banco vai de um estado válido para outro estado válido. Regras (constraints) nunca são violadas.

I — Isolamento

Transações paralelas não interferem entre si. Cada uma enxerga um "snapshot" consistente.

D — Durabilidade

Uma vez confirmada (COMMIT), a transação persiste mesmo que o servidor caia em seguida.

-- Transação bancária: transferir R$100 de Ana para Carlos BEGIN; -- inicia transação UPDATE contas SET saldo = saldo - 100 WHERE id = 1; -- debita Ana UPDATE contas SET saldo = saldo + 100 WHERE id = 2; -- credita Carlos COMMIT; -- confirma tudo junto -- Se qualquer UPDATE falhar: ROLLBACK automático
