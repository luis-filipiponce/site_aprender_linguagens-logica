Git — Controle de Versão

Git é o sistema de controle de versão mais usado no mundo. Criado por Linus Torvalds (criador do Linux) em 2005. Todo desenvolvedor profissional usa Git todos os dias. Sem exceção.

Git registra cada mudança no código como um "snapshot" (commit). Você pode voltar a qualquer ponto da história, criar branches paralelos, e colaborar com times de qualquer tamanho.

Comandos Essenciais

# Configuração inicial (uma vez só) git config --global user.name "Seu Nome" git config --global user.email "seu@email.com" # Iniciar repositório git init # cria .git/ no diretório atual git clone https://github.com/user/repo.git # clona do GitHub # Fluxo diário git status # ver o que mudou git diff # ver as diferenças linha a linha git add . # preparar tudo para commit (staging) git add arquivo.py # preparar arquivo específico git commit -m "feat: adicionar login com OAuth" # salvar snapshot # Branches — desenvolvimento paralelo git branch feature/login # criar branch git checkout feature/login # mudar para o branch git checkout -b feature/login # criar E mudar (atalho) git merge feature/login # integrar branch ao main git branch -d feature/login # deletar branch # Remoto (GitHub/GitLab) git push origin main # enviar commits git pull # baixar e integrar mudanças git fetch # baixar sem integrar git log --oneline --graph # histórico visual

Conventional Commits

Padrão de mensagens de commit usado por empresas para tornar o histórico legível e gerar changelogs automaticamente:

feat: adicionar autenticação com Google # nova funcionalidade fix: corrigir cálculo de desconto no carrinho # correção de bug docs: atualizar README com instruções de setup # documentação style: formatar código com black # formatação refactor: extrair lógica de envio de email # refatoração test: adicionar testes unitários para Produto # testes chore: atualizar dependências do requirements # manutenção

Boas Práticas de Código

DRY

Don't Repeat Yourself. Se o mesmo bloco de código aparece em dois lugares, extraia para uma função. Duplicação é a fonte de bugs difíceis.

KISS

Keep It Simple, Stupid. A solução mais simples que resolve o problema é a melhor. Complexidade desnecessária = dívida técnica.

YAGNI

You Ain't Gonna Need It. Não implemente funcionalidades que não foram pedidas hoje. Isso cria código morto e complexidade sem valor.

Single Responsibility

Cada função faz uma coisa. Cada classe tem um propósito. Funções com mais de 20 linhas geralmente estão fazendo coisas demais.

Princípios SOLID

LetraNomeO que significa
SSingle ResponsibilityUma classe/função = um único motivo para mudar.
OOpen/ClosedAberta para extensão, fechada para modificação.

DDependency InversionDependa de abstrações, não de implementações concretas.

Testes de Software

Código sem testes é código que você torce pra funcionar. Testes são a rede de segurança que permite refatorar e evoluir sem medo.

# pytest — testes unitários em Python def calcular_desconto(preco: float, pct: float) -> float: if not 0 <= pct <= 100: raise ValueError("Percentual deve estar entre 0 e 100") return preco * (1 - pct / 100) # arquivo test_desconto.py import pytest def test_desconto_10_porcento(): assert calcular_desconto(100.0, 10) == 90.0 def test_sem_desconto(): assert calcular_desconto(50.0, 0) == 50.0 def test_percentual_invalido_levanta_erro(): with pytest.raises(ValueError): calcular_desconto(100.0, 110) # 110% é inválido

Unitários

Testam funções/métodos isolados. Rápidos (milissegundos). Devem ser a maioria dos seus testes.

Integração

Testam componentes juntos: API + banco. Mais lentos, mas validam o fluxo completo.

E2E (End-to-End)

Simulam o usuário real no browser. Cypress, Playwright. Lentos, mas cobrem o fluxo completo.

TDD

Test-Driven Development: escreva o teste antes do código. Força você a pensar na interface antes da implementação.

Docker & Cloud

Docker empacota sua aplicação e todas as dependências em um container — um ambiente isolado que roda identicamente em qualquer máquina. "Funciona na minha máquina" nunca mais.

# Dockerfile — receita do container FROM registry.redhat.io/ubi9/python-311-minimal:latest WORKDIR /app COPY requirements.txt . RUN pip install --no-cache-dir -r requirements.txt COPY . . USER 1001 # nunca rodar como root! CMD ["uvicorn", "main:app", "--host", "127.0.0.1", "--port", "8000"]
# Comandos Docker básicos docker build -t meu-app . # construir imagem docker run -p 8000:8000 meu-app # rodar container docker ps # containers rodando docker logs meu-container # ver logs
