Como a Web Funciona

Quando você digita uma URL no browser e aperta Enter, uma cadeia precisa de eventos acontece em milissegundos:

1. Você digita: https://www.google.com 2. DNS Lookup — Quem é google.com? Browser → DNS Server → responde: 142.250.80.46 3. TCP Handshake — Conectar ao servidor Browser → Servidor: SYN Servidor → Browser: SYN-ACK Browser → Servidor: ACK ✅ Conectado! 4. TLS Handshake (HTTPS) — Criptografar tudo Troca de certificados e chave de sessão 5. Requisição HTTP GET / HTTP/2 Host: www.google.com Accept: text/html 6. Resposta HTTP HTTP/2 200 OK Content-Type: text/html [corpo HTML da página] 7. Browser renderiza HTML + CSS + executa JavaScript

Códigos de Status HTTP

DOM: Árvore, Eventos e Delegação

O DOM (Document Object Model) é a representação do HTML como uma árvore de objetos que o JavaScript pode ler e alterar. Eventos "sobem" pelos ancestrais (bubbling), o que permite a delegação de eventos: um único listener no elemento pai atende todos os filhos, inclusive os criados depois.

// Seleção, classes e atributos const lista = document.querySelector("#tarefas"); const itens = document.querySelectorAll("#tarefas li"); lista.classList.toggle("destaque"); lista.dataset.total = itens.length; // atributo data-total // Delegação de eventos: 1 listener para todos os botões "remover" lista.addEventListener("click", (e) => { const btn = e.target.closest("button.remover"); if (btn) btn.closest("li").remove(); }); // Formulário: cancelar o envio padrão e ler os campos document.querySelector("#form").addEventListener("submit", (e) => { e.preventDefault(); const dados = Object.fromEntries(new FormData(e.target)); console.log(dados); }); // Segurança: textContent trata como texto; innerHTML interpreta HTML (risco de XSS) lista.append(Object.assign(document.createElement("li"), { textContent: entradaDoUsuario }));

Web Storage e JSON

localStorage persiste dados no navegador; sessionStorage vale só para a aba. Guardam apenas strings, por isso usamos JSON. Nunca armazene senhas ou tokens sensíveis — qualquer script da página consegue lê-los.

// Salvar e carregar preferências com tratamento de erro localStorage.setItem("prefs", JSON.stringify({ tema: "escuro" })); function carregarPrefs() { try { return JSON.parse(localStorage.getItem("prefs")) ?? { tema: "claro" }; } catch { return { tema: "claro" }; // JSON inválido → valor padrão } } // IntersectionObserver: carregar imagens só quando ficam visíveis const obs = new IntersectionObserver((entradas) => { entradas.forEach((en) => { if (en.isIntersecting) { en.target.src = en.target.dataset.src; obs.unobserve(en.target); } }); }); document.querySelectorAll("img[data-src]").forEach((img) => obs.observe(img));

Back-end — O Que Roda no Servidor

O back-end processa a lógica de negócio, acessa bancos de dados, autentica usuários e serve dados ao front-end. O usuário nunca vê o back-end diretamente.

API REST com Python (FastAPI)

from fastapi import FastAPI, HTTPException from pydantic import BaseModel app = FastAPI() class Produto(BaseModel): nome: str preco: float banco_fake = [ {"id": 1, "nome": "Notebook", "preco": 3500.0}, {"id": 2, "nome": "Mouse", "preco": 89.90}, ] @app.get("/produtos") def listar_produtos(): return banco_fake @app.get("/produtos/{id}") def buscar_produto(id: int): p = next((x for x in banco_fake if x["id"] == id), None) if not p: raise HTTPException(404, "Produto não encontrado") return p @app.post("/produtos", status_code=201) def criar_produto(produto: Produto): novo = {"id": len(banco_fake)+1, **produto.dict()} banco_fake.append(novo) return novo

Desenvolvimento Mobile

📱 Android Nativo (Kotlin)

Linguagem oficial do Android desde 2019. Acesso total a todos os recursos do dispositivo. Coroutines para async e null safety embutida. Deploy na Play Store.

🍎 iOS Nativo (Swift)

Linguagem da Apple desde 2014. Performance máxima no ecossistema Apple. SwiftUI para interfaces declarativas. Obrigatória para App Store.

⚛️ React Native

Um código TypeScript para Android e iOS. Desenvolvido pelo Meta. Usa componentes nativos reais, não WebView. Expo facilita o início rápido.

🐦 Flutter (Dart)

Framework do Google. Performance próxima ao nativo. UI consistente em mobile, web e desktop. Widget tree declarativo parecido com React.

Cross-platform vs Nativo: Apps nativos têm melhor performance e acesso a APIs do dispositivo. Apps cross-platform (React Native, Flutter) economizam tempo — um time, dois sistemas operacionais. Para jogos, prefira Unity (C#).

⚛️ React e o Ecossistema Front-end Moderno

React (Meta, 2013) é a biblioteca mais usada para construir interfaces. Não é um framework completo — mas em torno dele existe um ecossistema rico:

// React + TypeScript — Componente funcional com hooks import { useState, useEffect } from "react"; interface Tarefa { id: number; titulo: string; feita: boolean; } export function ListaTarefas() { // Estado local — re-renderiza quando muda const [tarefas, setTarefas] = useState<Tarefa[]>([]); // Efeito colateral — busca dados ao montar o componente useEffect(() => { fetch("/api/tarefas") .then(r => r.json()) .then(setTarefas); }, []); // [] = executa só 1x const marcarFeita = (id: number) => setTarefas(prev => prev.map(t => t.id === id ? { ...t, feita: !t.feita } : t)); return ( <ul> {tarefas.map(t => ( <li key={t.id} onClick={() => marcarFeita(t.id)} style={{ textDecoration: t.feita ? "line-through" : "none" }}> {t.titulo} </li> ))} </ul> ); }

▲ Next.js 14 — Full-Stack React

App Router com Server Components (zero JS no cliente). Server Actions para mutations sem API REST. SSR, SSG e ISR para máxima performance e SEO. O framework React mais popular em produção.

💚 Vue 3 + Nuxt

Framework progressivo com sintaxe de template intuitiva. Composition API parecida com React hooks. Nuxt é o equivalente do Next.js para Vue — SSR e geração estática.

🔥 Svelte + SvelteKit

Compila para JavaScript puro — sem virtual DOM, sem runtime. Código mais conciso e performance excelente. SvelteKit é o framework full-stack oficial.

🌀 TailwindCSS

CSS utility-first — componha estilos com classes diretamente no HTML. Elimina conflitos de CSS, facilita dark mode e responsividade. Adotado por 40%+ dos projetos React em 2024.

GraphQL vs REST — Evolução das APIs

REST é o padrão dominante, mas GraphQL resolve problemas específicos: over-fetching (dados desnecessários) e under-fetching (múltiplas requisições).

🔵 REST — O Padrão

  • Endpoints fixos: GET /usuarios, POST /pedidos
  • Fácil caching com HTTP
  • Amplamente suportado por ferramentas
  • Ideal para APIs simples e públicas

🟣 GraphQL — A Alternativa Flexível

  • Um único endpoint: POST /graphql
  • Cliente escolhe exatamente o que receber
  • Evita over/under-fetching
  • Ideal para front-ends complexos e mobile
# GraphQL — Query: busca só o que precisa query { usuario(id: 1) { nome email pedidos(limit: 5) { id total status } } } # Resposta JSON exata — sem campos extras { "data": { "usuario": { "nome": "Ana", "email": "ana@email.com", "pedidos": [{ "id": 42, "total": 350.00, "status": "entregue" }] } } }
WebSockets & Server-Sent Events: Para dados em tempo real (chats, notificações), use WebSockets (bidirecional) ou SSE (servidor → cliente). Exemplos: Socket.io, Ably, Pusher. GraphQL Subscriptions usa WebSockets por baixo.

☁️ Microsserviços, Cloud & Containers

Arquitetura moderna divide a aplicação em serviços independentes, cada um com sua responsabilidade, banco de dados e ciclo de deploy.

🐋 Docker — Containers

Empacota a aplicação + dependências em uma imagem portátil. docker build → docker run. Docker Compose orquestra múltiplos serviços localmente.

☸️ Kubernetes — Orquestração

Gerencia containers em produção: autoscaling, health checks, rolling updates e service discovery. EKS (AWS), GKE (Google) e AKS (Azure) são as ofertas gerenciadas.

🔀 API Gateway

Ponto de entrada único para todos os microsserviços. Autentica, roteia, faz rate limiting e logging centralizado. Kong, AWS API Gateway, NGINX.

📨 Message Brokers

Kafka (alto volume, streaming), RabbitMQ (filas tradicionais) e SQS (AWS) desacoplam serviços. Produtor não espera pelo consumidor — resiliência natural.
